# LogSentry

A lightweight, dependency-free Python tool that analyses Linux `sshd` auth logs and Apache/Nginx
access logs, detects common attack patterns and maps each finding to the **MITRE ATT&CK** framework.
Built as a small SOC / blue-team exercise: parse -> detect -> triage -> report.

> All sample data in this repo is **synthetic** (documentation IP ranges, generated by a script).

## Detections

| Rule | What it looks for | Severity | MITRE ATT&CK |
|------|-------------------|----------|--------------|
| `ssh_bruteforce` | N failed SSH logins from one IP inside a sliding time window | High | T1110 Brute Force |
| `ssh_bruteforce` (escalated) | Successful login right after a brute-force burst | **Critical** | T1110 -> T1078 Valid Accounts |
| `web_attack` | SQLi, XSS, path traversal, command injection in URLs (URL-decoded twice to catch simple evasion) | High | T1190 |
| `scanner_user_agent` | sqlmap, nikto, gobuster, nmap, nuclei, etc. | Medium | T1595.002 |
| `directory_enumeration` | Burst of HTTP 404s from one IP | Medium | T1595.003 |

## Quick start

```bash
git clone https://github.com/mahesh0201/logsentry.git
cd logsentry
python samples/generate_samples.py          # creates synthetic samples/auth.log and samples/access.log
python -m logsentry --auth samples/auth.log --year 2026 --access samples/access.log
```

Options: `--threshold 5` `--window 10` (minutes) `--format markdown|json` `--output report.md`.

The exit code is `2` when high/critical findings exist and `0` otherwise, so it can gate a cron job or CI step.
See [`samples/example_report.md`](samples/example_report.md) for real output.

## Project layout

```
logsentry/
  parsers.py     regex parsers for auth.log and combined access logs
  detectors.py   detection rules (sliding-window logic + signatures)
  report.py      Markdown / JSON report builders
  cli.py         argparse command line interface
tests/           pytest unit tests (parsers, each rule, false-positive checks, CLI)
```

## Run the tests

```bash
pip install -r requirements-dev.txt
pytest -q
```

## Design notes and limitations

- Signature matching is intentionally simple and **will** produce false positives/negatives;
  production detection needs tuning, allow-lists and correlation (e.g. in Splunk/Elastic).
- Timestamps in `auth.log` have no year, so `--year` is required for accuracy.
- IPv4 only; no log rotation handling.
